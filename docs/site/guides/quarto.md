## Overview

Framework uses [Quarto](https://quarto.org) to render notebooks, documents, and presentations. When it creates a project, it writes `_quarto.yml` files that set rendering defaults and send rendered output to a separate folder. Python chunks in `.qmd` files run through Jupyter.

Quarto is a tool that a project can turn off. It is on for every project type except `bare`, and `tools={"quarto": False}` in [new()](ref:new) creates a project without the `_quarto.yml` files. Such a project records `quarto: false` under `tools` in `settings.yml`. Its notebooks are Jupyter notebooks, so [make_notebook()](ref:make_notebook) creates `.ipynb` files, and [quarto_regenerate()](ref:quarto_regenerate) refuses to run there. The [New Project](guide:new-project#tools-and-sets) guide covers tools.

## Render Folders

Framework keeps source files and rendered output apart. A `.qmd` file stays in its source folder, and the rendered HTML goes to a render folder. Rendered files can then be ignored, regenerated, or published without mixing them with the sources.

The `render_dirs` section of the settings maps each source folder to its render folder. These are the defaults.

| Project type | Source folder | Render folder | Format |
|--------------|---------------|---------------|--------|
| Standard | `notebooks/` | `outputs/notebooks/` | HTML |
| Standard | `docs/` | `outputs/docs/` | HTML |
| Privacy-sensitive | `notebooks/` | `outputs/private/notebooks/` | HTML |
| Privacy-sensitive | `docs/` | `outputs/private/docs/` | HTML |
| Course | `slides/` | `rendered/slides/` | reveal.js |
| Course | `assignments/` | `rendered/assignments/` | HTML |
| Course | `course_docs/` | `rendered/course_docs/` | HTML |
| Course | `modules/` | `rendered/modules/` | HTML |
| Presentation | project root | project root | reveal.js |

Folders whose key contains `slide` render as reveal.js presentations, and the others render as HTML. In privacy-sensitive projects, rendered notebooks land in a private folder, because they can contain restricted data.

## Generated Files

A standard project gets a root `_quarto.yml` and one in each source folder.

```text
vaccine-study/
├── _quarto.yml          # root configuration
├── notebooks/
│   ├── _quarto.yml      # sends output to ../outputs/notebooks
│   └── exploration.qmd
├── docs/
│   └── _quarto.yml      # sends output to ../outputs/docs
└── outputs/
    └── notebooks/       # rendered notebooks appear here
```

A source folder's file sets the output folder and the format options.

```yaml
# Auto-generated by Framework on 2026-10-31
# This file is yours to customize - Framework will not modify it after creation
# To regenerate: run framework.quarto_regenerate() (WARNING: overwrites!)

project:
  output-dir: ../outputs/notebooks

format:
  html:
    theme: default
    toc: true
    toc-depth: 3
    code-fold: false
    code-tools: false
    embed-resources: true
    highlight-style: github
```

Framework writes these files once. Edit them freely, because Framework does not change them afterward unless you call [quarto_regenerate()](ref:quarto_regenerate).

## Rendering Defaults

The values in the generated files come from the `quarto` section of the settings. Keys use underscores in the settings and hyphens in `_quarto.yml`.

```yaml
quarto:
  html:
    theme: default
    embed_resources: true
    toc: true
    toc_depth: 3
    code_fold: false
    code_tools: false
    highlight_style: github
  revealjs:
    theme: default
    incremental: false
    slide_number: true
    transition: slide
    background_transition: fade
    controls: true
    progress: true
    center: true
    highlight_style: github
```

Changing this section does not change existing `_quarto.yml` files. Regenerate them to apply new values.

## Regenerating

[quarto_regenerate()](ref:quarto_regenerate) rewrites every `_quarto.yml` from the project's settings. It overwrites manual edits, so it first copies the existing files into `.quarto_backups/<timestamp>/`.

```python
import framework as fw

result = fw.quarto_regenerate(".")
result.regenerated
result.backup_location
```

Pass `backup=False` to skip the copy. [quarto_generate_all()](ref:quarto_generate_all) writes the files from explicit arguments and is what project creation uses.

## Creating Quarto Files

[make_notebook()](ref:make_notebook) and [make_qmd()](ref:make_qmd) create notebooks, and [make_presentation()](ref:make_presentation) creates reveal.js slides. The [Notebooks and Scripts](guide:notebooks) guide describes them.

## Rendering

Quarto runs Python chunks with Jupyter, which must be installed in the environment that renders. Add it to the project once.

```python
fw.package_add("jupyter")
```

Render from the terminal with the project's environment.

```sh
uv run quarto render notebooks/exploration.qmd
```

[save_notebook()](ref:save_notebook) renders a notebook and saves the result in the notebooks output folder, where it is recorded in `framework.db` with the other outputs.

```python
fw.save_notebook("notebooks/exploration.qmd")
fw.save_notebook("notebooks/exploration.qmd", name="exploration-2026-10", format="pdf")
```

The formats are `html`, `pdf`, and `docx`. HTML is rendered as one self-contained file unless you pass `embed_resources=False`. `quarto_args` passes extra arguments to `quarto render`. `save_notebook()` also renders Jupyter notebooks (`.ipynb`).

## Publishing

[publish_notebook()](ref:publish_notebook) renders a notebook and uploads the result to a storage bucket or to Framework Cloud. The [Publishing](guide:publishing) guide covers both.
